# Security & Compliance Rules

Mandatory security hardening, data privacy compliance, and threat mitigation standards for all landing pages generated by this skill. A landing page is frequently the primary public entry point of a business; security flaws compromise user trust, degrade ad campaign quality scores, and expose organizations to legal liabilities.

---

## 1. Content Security Policy (CSP)

Every landing page must either declare a strict CSP via HTTP response headers or include a `<meta http-equiv="Content-Security-Policy">` tag.

### Recommended Production CSP Meta Tag

```html
<meta http-equiv="Content-Security-Policy" content="
  default-src 'self';
  script-src 'self' 'unsafe-inline' https://www.googletagmanager.com https://www.google-analytics.com https://connect.facebook.net;
  style-src 'self' 'unsafe-inline' https://fonts.googleapis.com;
  font-src 'self' https://fonts.gstatic.com data:;
  img-src 'self' data: https: blob:;
  connect-src 'self' https://www.google-analytics.com https://api.formspree.io https://*.supabase.co https://api.webhooks.com;
  frame-ancestors 'none';
  base-uri 'self';
  form-action 'self' https:;
" />
```

### Key CSP Rules:
1. **Clickjacking Prevention (`frame-ancestors 'none'` / `X-Frame-Options: DENY`):** Disallow embedding in unauthorized iframes to prevent clickjacking attacks where malicious overlays hijack user clicks.
2. **Restricted Form Action (`form-action 'self' https:`):** Prevent form submissions from being redirected to unencrypted or arbitrary third-party endpoints.
3. **No Unrestricted Scripts:** Never use `*` wildcards in `script-src` or `connect-src`.

## 2. DOM-Based Cross-Site Scripting (XSS) Prevention

Landing pages that employ dynamic query parameter insertion (such as Dynamic Text Replacement or UTM parameter capture) are vulnerable to DOM-based XSS if user inputs are reflected without sanitization.

### Prohibited Patterns:
* **NEVER** use `element.innerHTML = urlParam`
* **NEVER** use `document.write(urlParam)`
* **NEVER** use `eval()` or `new Function()`
* **NEVER** insert unescaped parameters into inline event handlers (e.g. `onclick="track('${param}')"`)

### Required Pattern (Safe Parameter Insertion):
Always use `element.textContent` or create text nodes. `textContent` automatically treats all inputs as plain strings, completely neutralizing script tags, quotes, and HTML entities:

```javascript
// SAFE: Extracts and sets as raw text
const params = new URLSearchParams(window.location.search);
const audienceParam = params.get('audience');

if (audienceParam) {
  const sanitized = audienceParam.replace(/[^a-zA-Z0-9 _-]/g, '').slice(0, 40);
  const targetElement = document.getElementById('dynamic-audience-text');
  if (targetElement) {
    targetElement.textContent = sanitized;
  }
}
```

## 3. Lead Capture & Form Security

Forms are the primary attack surface on landing pages for bot spam, credential stuffing, and payload injection.

### A. Dual Honeypot Protection (Zero CAPTCHA Friction)
Never use intrusive puzzle CAPTCHAs on high-converting landing pages unless under active attack. Instead, implement a multi-layered invisible bot trap:

1. **Invisible Honeypot Field:** Hidden via CSS and off-screen coordinates. If filled, abort submission silently.
2. **Submission Timestamp Threshold:** Record the page render timestamp. Human form completions take at least 2.5–3 seconds. Any submission under 1.5 seconds is automated spam.

```html
<!-- Honeypot: Hidden from sighted users and screen readers -->
<div style="position: absolute; left: -9999px; top: -9999px;" aria-hidden="true">
  <label for="hp_field_company">Leave this field empty</label>
  <input type="text" id="hp_field_company" name="hp_field_company" tabindex="-1" autocomplete="off" />
</div>
<!-- Timestamp token -->
<input type="hidden" id="form_timestamp" name="_form_ts" />
```

### B. Client-Side Submission Rate Limiting (Flood Prevention)
Prevent rapid repeated clicks or script-triggered submission flooding:
* Disable the submit button immediately upon first click and show a loading spinner.
* Debounce submissions to a minimum interval of 5 seconds per browser session.
* Store last submission timestamp in `sessionStorage`.

### C. Input Sanitization & Validation
* Validate email format with strict regex on blur and on submit.
* Impose strict `maxlength` attributes on all inputs (`maxlength="100"` on name, `maxlength="120"` on email, `maxlength="500"` on messages).
* Disallow executable strings or script tags in inputs.

## 4. Hyperlink & Outbound Navigation Safety

Every external link that opens in a new tab (`target="_blank"`) introduces a reverse tabnabbing vulnerability where the target page can execute `window.opener.location = 'phishing-url'`.

### Mandatory Link Policy:
```html
<!-- REQUIRED on all external links -->
<a href="https://partner.com" target="_blank" rel="noopener noreferrer">
  Partner Name
</a>
```
* `noopener`: Cuts off access to the `window.opener` object.
* `noreferrer`: Prevents the `Referer` header from leaking sensitive URL parameters or internal tokens to external domains.

## 5. Data Privacy & Compliance (GDPR, CCPA, ePrivacy)

High-converting landing pages running paid traffic must adhere to international privacy regulations to avoid campaign suspension or regulatory penalties.

1. **Cookie & Tracking Consent:**
   * Non-essential tracking pixels (Meta Pixel, TikTok, LinkedIn) and marketing cookies must not fire before explicit consent if targeting EEA/UK visitors.
   * Provide a persistent, accessible consent banner or hook to Google Consent Mode v2 (`analytics_storage: 'denied'`, `ad_storage: 'denied'`).

2. **No PII in URLs or Analytics:**
   * Never pass unhashed emails, phone numbers, or full names in URL query strings.
   * Strip sensitive fields from analytics events and pageview URLs.

3. **Consent Checkbox on Forms:**
   * Lead capture forms must include an explicit consent notice with direct links to the Privacy Policy and Terms of Service:
     ```html
     <p class="form__legal">
       By submitting, you agree to our <a href="/privacy" rel="noopener">Privacy Policy</a>. We never sell your data.
     </p>
     ```

## 6. Subresource Integrity (SRI)

When loading third-party scripts or styles from public CDNs, always specify the `integrity` hash and `crossorigin="anonymous"`:

```html
<link 
  rel="stylesheet" 
  href="https://cdnjs.cloudflare.com/ajax/libs/normalize/8.0.1/normalize.min.css" 
  integrity="sha512-NhSC1YmyruXifcj/KFRWoC561YpHpc5Jtzgvbuzx5VozKpWvQ+4nXhPdFgmx8xqexRcpAglTj9sIBWINXa8x5w==" 
  crossorigin="anonymous" 
  referrerpolicy="no-referrer" 
/>
```
